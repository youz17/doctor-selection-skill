# 医生信息源手册

> 目标：在信息不对称的条件下，用可验证的渠道拼出一个医生的完整画像——**身份、方向、临床角色、同行认可、患者体验**，并知道每条信息有多可信。
> 本文与医院无关；所有「实测」均为 2026-10-19 的实际访问记录，仅作示例。

## 0. 三条使用规则

1. **分层取数**：身份类信息只信官方，体验类信息看平台，同行认可看学术，三者不混用。
2. **交叉验证**：单一来源的结论一律标注为「待核」；至少两个独立来源一致才算事实。
3. **带时点引用**：医生职称、排班、简介都会变，任何结论后面都要跟「截至某日」。
4. **工具自己选**：脚本、浏览器（browser skill / 直接 CDP）、手工复制都行，只看结果是否可核对。
   官网是 JS 渲染、要登录、要翻页时，**优先开浏览器读**，不要为了「纯脚本」硬啃接口；
   反过来，批量、可重复、要留痕的活，写成脚本（本仓库的 `scripts/`）。判断标准只有两条：
   能不能拿到、能不能复核。

> 写这段的目的：给 AI 更大的自主权。渠道会改版，固定套路会过时，
> 「先探明结构、再决定用脚本还是浏览器」比「必须用某种技术」更重要。

## 1. 先定义要哪些信息

| 信息层 | 具体字段 | 主要来源 | 可信度 |
| --- | --- | --- | --- |
| 身份 | 姓名、性别、科室、职称、执业地点 | 医院官网、卫健委注册查询 | 高 |
| 专业 | 亚专业方向、擅长病种/术式、专病门诊 | 医院官网专家简介 | 中高（自述） |
| 临床角色 | 科室职务、手术/介入量、带组、质控 | 官网简介、会议报道、同行 | 中 |
| 学术 | 学会任职、指南/共识、科研项目 | 学会名单、PubMed、国自然 | 中高 |
| 服务 | 出诊时间、院区、挂号方式、停诊 | 官网排班、挂号平台 | 高（时效短） |
| 口碑 | 患者反馈、病友评价 | 好大夫、病友群、社区 | 低到中（样本偏差） |

**先定字段再选渠道**，可以避免被某一个平台牵着走。

## 2. 一手官方源

### 2.1 医院官网

最可靠、信息最全，也是唯一能拿到「官方职称 + 官方擅长 + 官方排班」的地方。

**几乎所有医院都是同一个三层结构：**

```text
① 科室索引（科室导航 / 专家团队 / 特色专科）
      ↓
② 科室页（该科室全部医生：姓名 + 详情链接）
      ↓
③ 医生详情页（职称、擅长、简介、学术任职）＋ 独立的排班接口
```

**三种技术形态**（按出现频率排序）：

| 形态 | 特征 | 取法 |
| --- | --- | --- |
| 服务端渲染 | 查看网页源代码就能看到医生姓名 | 直接解析 HTML |
| 前端 AJAX 填充 | 源码里只有空容器 + 一个 `value`/`token` | 从页面提取参数，复现那个 POST |
| 独立 JSON API | DevTools → Network → XHR/Fetch 里有 `.json` 或 `GetXxx` | 直接请求，最干净 |

**怎么快速判断**：打开科室页 → F12 → Network 勾选 XHR → 刷新 → 看有没有返回医生列表的请求；再点进一个医生，看详情是 HTML 还是 JSON。

**能拿到**：姓名、职称、科室、擅长、简介全文、学术任职、门诊时段、近期排班、照片、详情链接。
**坑**：

- 有的科室页只放「精选专家」，全部医生要点「查看更多」或另一层页面；
- 部分科室（尤其医技、行政科室）根本没有专家名单；
- 简介是自述，只讲长处，不写手术并发症；
- 多院区医院，同一医生在不同院区的团队与号源不同；
- 网页改版会让 AJAX 的 token 机制失效。

### 2.1.1 拿不到时的第二条路：用浏览器读

同一个官网，三种形态对应三种取法。**不要因为「写不出脚本」就放弃这家医院**：

| 情况 | 脚本 | 浏览器 |
| --- | --- | --- |
| 服务端渲染 | 首选，快、可批量 | 备用 |
| 空壳 + token，但参数能复现 | 可以写 | 也可以 |
| 登录态 / 强 JS / 滑块 / 频控 | 放弃 | **首选**（browser skill 或 CDP 驱动已登录浏览器） |

浏览器的取数流程（人机都适用）：

1. 打开科室索引，确认科室页 URL 规律；
2. 打开一个科室页，若列表要「加载更多」，先滚动到底；
3. 用页面文本抽取（而不是盯 DOM 猜 class）：姓名、职称、擅长、出诊；
4. 逐页翻，边翻边记 `抓取日期 + 页面 URL`；
5. 遇到登录墙/验证码就停——换成「人工看、人工记」，不绕过。

**记录要求不变**：一条记录 = 一个详情页 URL（主键），字段与 `data/*.json` 同构，
这样浏览器拿到的数据也能直接进 `query.py` / `verify.py`。

> 经验：官网这种「权威但不友好」的源，浏览器路径的产出质量往往高于脚本，
> 因为人（或 AI）能顺手判断「这条是精选专家还是全量」「这个科室是不是医技科室」。

### 2.2 医院公众号 / APP / 小程序

挂号入口常在这里，能拿到**真实号源与停诊信息**，但医生资料通常比官网简略。
适合：确认某医生本周是否出诊、能否加号。

### 2.3 官方挂号平台（自建 / 114 / 健康之路 / 微医）

能拿到号源、门诊类型（普通/专家/特需/名医）、院区。
**注意**：门诊类型不代表水平，「特需/国际部」卖的是时间与服务，不是技术。

### 2.4 卫健委执业注册查询

国家卫健委「医生执业注册信息查询」可核验：执业地点、执业范围、执业证书编码。
用途：确认这个人确实注册在这家医院、执业范围与科室一致（防「假专家」「走穴」）。
**实测**：2026-10-19 从当前网络访问 `zgcx.nhc.gov.cn:9090/doctor` 返回 **403（WAF 拦截）**，换网络或走省级卫健委入口通常可用。
**坑**：只证明「有执业资格、注册在此」，不证明水平；多点执业可能不在同一页面显示。

### 2.5 医院公告、科室介绍、招聘公告

侧面信息：科室简介会写亚专业分组、床位、年手术量；招聘公告会暴露科室扩张方向。
适合：判断一个科室的整体实力与亚专业设置。

## 3. 第三方医生平台

### 3.1 好大夫在线

**页面结构**：医生主页 = 简介 / 出诊 / 疗效反馈（患者感谢信、投票）/ 同科室推荐。
**能拿到**：患者侧反馈、出诊时间（可与官网交叉验证）、医生自己写的科普文章。

**实测（2026-10-19，同济心内科一位医生）**：

| 项目 | 平台显示 | 与官网对比 |
| --- | --- | --- |
| 职称 | 副主任医师 | 官网已更新为主任医师（**滞后**） |
| 简介 | 2013 年博士毕业、访问学者、SCI 十余篇 | 官网已补充「科室副主任、数千例手术、主力术者」 |
| 出诊 | 与官网排班一致 | **可交叉验证** |
| 疗效反馈 | 1 条，匿名，无文字 | 样本不足以判断 |

同一页「同科室医生」栏的「在线服务患者数」：一位介入量很高的主任医师只有 13，另一位 731。
**说明该指标衡量平台活跃度，不是临床水平。**

**正确用法**：补患者体验、核对出诊；不用于判断技术高低；职称与简介以官网为准。

**2026-10-20 复核**：医生主页与疾病推荐页都能直接 GET 解析，**不需要登录**；
站点搜索是 JS 驱动（`/ssDoctor?kw=` 会 301 回首页），所以入口靠疾病页 / 医院页 / 搜索引擎。

可直接解析的字段：

| 页面上 | 字段 | 可信度 |
| --- | --- | --- |
| `h1` / `.doctor-title` | 姓名、职称 | 中（常滞后官网，仅作对照） |
| 医院 / 科室链接 | 执业地点 | 高 |
| `.expertise-content-wrap` | 擅长 | 中（自述） |
| `.doc-introduction` | 简介 | 中（自述，比官网简） |
| `.introwarp` | 社会任职、科研成果 | 中高 |
| `.schedule-item` | 出诊日期/时段/门诊类型 | 高（与官网交叉验证） |
| 「诊后评价 共 N 个」 | 评价总量 | 中（平台活跃度代理） |
| `.vote-item` | 各病种投票数 | 中（病种结构比总数有用） |
| `.honor-title` | 「20XX 年度好大夫」 | 低（平台自颁） |

疾病推荐榜：`/citiao/jibing-<拼音>/tuijian-doctor.html`，一页 15 位医生，
卡片上直接给出**病种票数、主观疗效/态度满意度、推荐度、问诊价格**——
比医生主页更适合「同病种横比」，但排序依据是平台票数，**不是临床水平**。

```bash
python scripts/fetch_haodf.py --doctor https://www.haodf.com/doctor/246844.html
python scripts/fetch_haodf.py --list https://www.haodf.com/citiao/jibing-gaoxueya/tuijian-doctor.html --limit 10
```

输出在仓库字段基础上追加 `source, fetched_at, review_count, votes, satisfaction, recommend, honors`，
`query.py` 可直接检索。

**坑**：

- 榜单是「全国 + 全病程」混排，和地方、亚专业都对不上，只用来找名字，不用来下结论；
- 满意度接近 100% 是常态（差评会被折叠/协商），不能当质量指标；
- 平台会推荐「同科室其他医生」，那是导流位，不是学术排序。

### 3.2 微医（guahao.com）

挂号与图文问诊入口，号源较全。
**实测（2026-10-20）**：首页返回 988 字节的 EdgeOne 机器人挑战脚本（`EO_Bot_Ssid`），
自动化不可行，需人工在浏览器里操作——属于平台策略，不是脚本 bug。

### 3.3 其他平台

| 平台 | 特点 | 用途 |
| --- | --- | --- |
| 百度健康 | 医生主页 + 挂号 + 问诊 | 号源、科普 |
| 京东健康 | 问诊为主 | 线上咨询 |
| 健康之路 | 挂号、体检 | 号源 |
| 丁香医生 | 科普与用药查询 | 疾病知识，不看医生排名 |

这类平台的医生资料多与官网重合，价值主要在**号源**与**线上问诊入口**，注意商业导流。

### 3.4 平台数据的三种系统性偏差

| 偏差 | 表现 | 后果 |
| --- | --- | --- |
| 滞后 | 职称、简介停留在两三年前 | 把副主任当现状 |
| 样本 | 评价只有几条，且好评者更愿意写 | 小样本被当成口碑 |
| 活跃度 | 「在线服务患者数」「推荐票」高 | 被误读为水平高 |

## 4. 学术与行业源

- **学会任职**：委员 → 常委 → 副主委 → 主委；青委含金量低于同级别委员；学组任职要看是否对口你的病种。
- **指南/共识**：参与国家级指南编写，通常说明在该亚专业有话语权。
- **论文**：PubMed 用「作者拼音 + 单位」检索，CNKI/万方可查中文；注意同名同单位。
  看**方向是否与亚专业一致**，不看数量；临床研究（队列、术式对比）比纯基础更贴近看病。
- **国家自然科学基金**：查主持项目与年份，判断科研体量，只覆盖纵向课题。
- **复旦版《中国医院专科声誉排行榜》**：只到科室层面，适合选医院，不适合选到人。
- **会议报道 / 科室动态**：学术会议讲者、手术直播、新技术开展，是「还在临床一线」的旁证。

### 4.1 自动化程度（2026-10-20 实测）

| 源 | 状态 | 说明 |
| --- | --- | --- |
| PubMed E-utilities | **可用** | `eutils.ncbi.nlm.nih.gov`，无需 key，限 3 请求/秒；`fetch_pubmed.py` 已封装 |
| PubMed 网页 | 203 挑战 | 页面在部分网络返回挑战页，不要依赖网页版抓取 |
| 国自然（kd.nsfc.cn） | 需登录 | 接口 401「暂未登录或 token 过期」，只能人工查 |
| 复旦医院排行榜 | 当前不可达 | `fudanmed.com` 连接超时；改用医院官网「国家临床重点专科」名单 |
| 学会名单 | 人工 | 多为 PDF / 图片 / 需要登录的会员区 |

查论文的正确姿势是「作者拼音 + 单位」，而不是姓名：

```bash
python scripts/fetch_pubmed.py --author "Shen Chengxing" --affiliation "Shanghai Sixth" --years 2018-2026
```

输出：总命中数、年度分布、第一作者命中数、每篇的期刊/年份/作者/链接。
**怎么读**：看方向是否与你的病种一致、近三年是否还有临床研究；
不看篇数排名，也不把基础研究当成临床水平。

**坑**：拼音写法多样（Shen Chengxing / Shen C X / Cheng-Xing Shen），
中文名转拼音要试 2–3 种；同名同单位真实存在，必须结合亚专业人工核对。

## 5. 口碑与社区

**结论：社区只提供线索，不提供证据。** 详细用法、偏差表与操作路径见
[`docs/social-reviews.md`](social-reviews.md)，这里只留渠道判断。

| 渠道 | 实测（2026-10-20） | 适合 | 不适合 |
| --- | --- | --- | --- |
| 知乎 | 直连 403；真实浏览器可读 | 方法论、行业内视角、长文经历 | 查某个医生的水平 |
| 小红书 | 未登录跳登录页，搜索页返回空结果 | 就医流程、排队、费用体感、沟通风格 | 疗效、并发症、职称 |
| 微博 | 跳 Sina Visitor System | 停诊/公告转发、本地突发 | 系统性判断 |
| 病友群 / 病友组织 | 人工 | 同病种真实路径（找谁看、排多久） | 大样本统计 |
| 门诊服务台 / 护士站 | 人工 | 分诊、院区、流程 | 技术评价 |

取数方式：浏览器人工读（推荐），或把页面另存/正文复制后交给脚本离线整理。

```bash
python scripts/probe_sources.py --only 小红书,知乎,微博      # 先确认今天通不通
python scripts/fetch_social.py --html data/cache/note.html --watch 同济医院,沈成兴
python scripts/fetch_social.py --text data/cache/note.txt --platform xhs --watch 协和
```

用法不变：社区信息用来**发现问题**（停诊？排队？流程？），再用官方渠道**验证**。
**不要**用「小红书都说他好」作为推荐理由。

## 7. 交叉验证：三源规则

| 要确认的事 | 第一源 | 第二源 | 冲突时 |
| --- | --- | --- | --- |
| 职称、科室、执业 | 医院官网 | 卫健委注册 | 以官网 + 注册为准 |
| 亚专业方向 | 官网「擅长」 | 论文/学会学组 | 以官网 + 学会为准 |
| 是否出诊 | 官网排班 | 挂号平台 | 以挂号平台当日为准 |
| 临床水平 | 手术量/专病门诊 | 同行评价 | 标注为推断，不下定论 |
| 患者体验 | 好大夫 | 病友群 | 样本都小时只作参考 |

**推荐输出格式**：`结论（置信度）+ 依据（来源、日期）+ 反面可能`。

## 8. 数据治理（自己采集时）

- **主键**：详情页 URL 或院内编码，不要用姓名（同名不同人真实存在）。
- **去重**：同一人可能在多个科室出诊，合并科室而不是拆行。
- **清洗**：HTML 实体可能双重转义（`&amp;amp;` → `&amp;`），要反复 unescape；去掉零宽字符与全角空格；`<br>` 转换行。
- **质检**：空值率、简介长度分布、链接可达率、随机抽 20 条对照原页。
- **字段**：`hospital, dept, name, sex, title, goodat, intro, academic, clinic_time, schedule, url, photo`。

## 9. 合规与伦理

- 只采公开页面；不登录、不绕验证码、不使用未公开接口。
- 控制频率（单站并发 ≤ 6），不影响对方服务。
- 不采集患者信息、评论区个人信息。
