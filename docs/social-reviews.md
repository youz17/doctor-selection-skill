# 社交口碑：小红书 / 知乎 / 微博怎么用

> 结论先说：**社交平台只提供线索，不提供证据。**
> 它的价值是「发现问题」——某医生是不是停诊了、某院区排队多久、术后复查流程是什么；
> 不是「证明水平」——疗效、并发症、手术量，社区里没有可信样本。

---

## 1. 三个平台的实测状态（2026-10-19 / 20）

| 平台 | 直连（脚本） | 浏览器（登录态） | 能拿到 | 判断 |
| --- | --- | --- | --- | --- |
| 小红书 | 搜索页返回空壳（`search.feeds = []`），首页 302 到 `/login` | 弹「登录后查看搜索结果」 | 就医流程、费用体感、排队、医生沟通风格 | **必须登录，脚本不抓** |
| 知乎 | 403（`zh-zse-ck` 反爬） | 正常阅读，未登录也能看回答 | 方法论、行业内视角、长文经历 | 浏览器可读，适合「怎么选」而非「选谁」 |
| 微博 | 跳 `Sina Visitor System` | 需访客票据/登录 | 医院公告转发、突发停诊、本地讨论 | 时效强、噪声大 |

复跑这条判断：

```bash
python scripts/probe_sources.py --only 小红书,知乎,微博
```

**不要做的事**：不模拟登录、不逆向签名、不绕验证码。平台把内容放在登录之后，是明确的产品与合规边界；
绕过它拿到的数据也不能写进给患者的建议里。

## 2. 它到底能回答什么

| 问题 | 社区能不能答 | 该回到哪里验证 |
| --- | --- | --- |
| 这位医生停诊了吗 | 能（常有人发「停诊通知」） | 医院官网排班 / 挂号平台 |
| 挂他的号要等多久 | 能（经验值） | 挂号平台当日号源 |
| 门诊在哪个院区、几楼 | 能 | 医院官网/导诊台 |
| 术后复查流程、要带什么 | 能，且往往比官网细 | 出院小结、科室护士站 |
| 沟通风格、是否耐心 | 能（主观但相关） | 面诊时自判 |
| 手术做得好不好 | **不能** | 手术量、专病门诊、同行评价 |
| 有没有并发症 | **不能**（幸存者偏差 + 删帖） | 术前谈话、病历 |
| 职称、学术地位 | **不能**（常年不更新） | 官网、学会名单 |

一句话：**社区补「体验与流程」，官方补「身份与水平」。**

## 3. 五种偏差，先记住再读

| 偏差 | 表现 | 应对 |
| --- | --- | --- |
| 自选样本 | 写笔记的人，要么特别好要么特别差 | 只看「同类病例 + 具体细节」，不看情绪强度 |
| 情绪放大 | 「态度差」常源于等待时间，不是医术 | 把流程抱怨与技术评价分开记 |
| 软广/代挂 | 「加号」「内部号」「包成功」「私信」 | 出现即降权，直接丢弃 |
| 时间错位 | 三年前的笔记说「某主任」，人已调走 | 必须记发布日期，超过 18 个月只作历史 |
| 同名混淆 | 同院同科同名医生真实存在 | 用「医院+科室+职称」三元组核对 |

配套的机器可读标记由 `scripts/fetch_social.py` 自动打：
`疑似营销/代挂`、`含价格信息`、`负面表述`、`正面表述`、`过短`。

## 4. 三条操作路径（按合规优先级）

### 路径 A：浏览器读，人来判断（推荐）

用 browser skill，或任意浏览器 + CDP，打开笔记/回答，按「医院 / 医生 / 科室 / 日期 / 具体事实」四要素摘录。

要点：

- 只看**具体到流程**的句子（"周三上午在门诊 3 楼，先抽血再找医生看结果"），跳过形容词；
- 一条笔记只记 1–2 个可验证事实，其余归为「感受」；
- 截图若含他人信息，打码后再存。

### 路径 B：另存页面 → 脚本解析

浏览器里 `Ctrl+S` 存成 HTML（或从 DevTools 复制 `outerHTML`），再：

```bash
python scripts/fetch_social.py --html data/cache/xhs_note.html --watch 同济医院,沈成兴
```

脚本会读小红书 `window.__INITIAL_STATE__`、知乎 `div.AnswerItem`、微博正文节点；
**没有登录态时会明确报「页面里没有笔记数据」，不会瞎猜。**

### 路径 C：复制正文 → 脚本抽取

最省事：把正文复制到 `.txt`（或在知乎里 Ctrl+A 复制），

```bash
python scripts/fetch_social.py --text data/cache/note.txt --platform xhs --watch 协和,专家号
```

输出 JSONL，包含：平台、作者、日期、正文、字数、互动量、命中词、营销/价格/情绪标记。
适合批量整理十几条笔记，再人工合并成一张「体验线索表」。

## 5. 记录格式

```json
{"platform": "xhs", "url": "https://www.xiaohongshu.com/explore/<id>",
 "author": "…", "published_at": "2026-08-11",
 "text": "…", "chars": 259,
 "metrics": {"likes": 1200, "collects": 300, "comments": 88},
 "hits": {"协和": 2}, "flags": ["含价格信息"], "negative_terms": []}
```

引用规则：**平台 + 链接 + 日期 + 一句话事实**。
例：`2026-08-11 小红书笔记称「协和特需 600 元、专家号 100 元」，与官网特需价格不一致，待核。`

---

## 6. 反例（这样用就错了）

- 「小红书上都说他好」→ 30 条笔记抵不过一次官网排班核对，也证明不了疗效。
- 用笔记里的职称做推荐 → 平台职称常年滞后，官网可能早已晋升。
- 把「推荐医生」当广告位 → 这类内容多半是导流，不是体验。
- 拿社区内容预测手术结果 → 失败案例通常不会发帖。

---

## 7. 合规

- 不抓取、不模拟登录、不绕验证码；只处理你**有权看到**的页面。
- 不记录作者昵称、头像、病史等可识别个人的信息；引用时脱敏。
- 不把社区内容二次发布成「医生排名」。
